# LLVM Orderfiles Code Review Guide

## 1. Code Review Focus Areas

This component provides the tooling for generating, validating, and merging profile-guided function orderfiles used by LLVM's linker (`lld`) to optimize the layout of native `.text` sections in Android binaries (such as ART's `dex2oat`). Reviewers should focus on the following core domains:

- **Trace Decoding & MD5 Handling (`toolchain/llvm_android/orderfiles/scripts/create_orderfile.py`)**:
  - *Little-Endian Reconstruction*: Profiles generated by compiler runtime instrumentation (`__llvm_orderfile_dump()`) and dumped via `hexdump -C` store 64-bit truncated MD5 hashes in little-endian order. The script splits 8-byte hex segments (`line[1:9]` and `line[9:17]`), reverses them, and concatenates them to recover the compiler's mapping hash. Reviewers must ensure slicing offsets, hex string lengths, and byte reversals are strictly preserved.
  - *Startup Cutoff & Boundary Semantics*: When `--last-symbol` is specified, symbol collection must terminate immediately upon writing that symbol. Verify that no subsequent execution symbols leak into the startup section.
  - *Leftover Symbol Ordering*: Verify that unexecuted functions appended via `--leftover` do not disrupt the execution sequence established during cold-start tracing.

- **Graph Synthesis & Cycle Elimination (`toolchain/llvm_android/orderfiles/scripts/merge_orderfile.py`)**:
  - *Graph Construction*: Sequential function executions create directed edges ($u \to v$). Multiple traces or weighted trace inputs multiply edge weights. Reviewers must ensure vertex and edge weights represent frequency and device priority accurately.
  - *Cycle Detection & Breaking*: Non-deterministic thread execution or cross-device profile variance creates directed cycles. The algorithm detects elementary cycles using DFS back-edges (`__cyclesUtil`) and severs the inbound cycle edge targeting the vertex with the maximum external in-degree weight (`inner_weights`). Reviewers must verify that cycle edge removal correctly handles intersecting cycles and leaves the graph strictly acyclic (`assert len(graph.getCycles()) == 0`).
  - *Linearization Determinism*: Symbol ordering is generated via DFS starting from roots (vertices with in-degree 0), prioritizing highest-weight outgoing edges (`out_edges.sort(key=lambda x: x[1], reverse=True)`). Reviewers must verify that tie-breaking across equal weights is deterministic and does not rely on arbitrary hash map or set iteration.

- **Validation Gates & Correctness Checks (`toolchain/llvm_android/orderfiles/scripts/validate_orderfile.py`)**:
  - *Quality Assurance Gates*: Ensure validation strictly enforces all four gates:
    1. **Denylist Enforcement**: Immediate `RuntimeError` if any forbidden symbol is found.
    2. **Allowlist Completeness**: All required symbols must be present in the orderfile.
    3. **Minimum Symbol Count (`--min`)**: Prevents empty or truncated orderfiles from landing in prebuilts.
    4. **Partial Order Monotonicity**: Verifies that specified startup sequences are strictly non-decreasing in file position (`new_index >= old_index`).
  - *Denylist Priority*: If a symbol is present in both allowlist and denylist, the denylist must take unconditional precedence (`allowlist = allowlist.difference(inter)`).

- **Polymorphic Input Parsing (`toolchain/llvm_android/orderfiles/scripts/orderfile_utils.py`)**:
  - Reviewers must ensure the three polymorphic input formats are cleanly dispatched:
    - `@<file>`: One entry per line (or `filename,weight`), resolved relative to the list file's parent directory.
    - `^<folder>`: Directory containing `*.orderfile`, sorted alphabetically for reproducible merging.
    - `"csv,list"`: Comma-separated symbol or file tokens.
  - Ensure whitespace stripping and empty-line handling are robust across all input parsers.

## 2. Anti-Patterns & Common Pitfalls

- **Inverted Flag Dependencies**:
  - *Pitfall*: Gating optional flags on the presence rather than absence of conflicting flags (e.g. checking `args.leftover and args.last_symbol != None` when the intention is allowing leftover symbols only when `--last-symbol` was *not* provided).
  - *Review Check*: Scrutinize all compound flag conditions to ensure optional parameters do not accidentally become dead code when mutually exclusive flags are omitted.

- **Mutating Graphs During Cycle Collection Iteration**:
  - *Pitfall*: Collecting all cycles via `graph.getCycles()` and iterating through them while calling `graph.removeEdgeCompletely()`. In complex topologies with shared edges, removing an edge from one cycle may invalidate or mutate another cycle in the precomputed list.
  - *Review Check*: Ensure cycle elimination either recalculates cycles dynamically or verifies edge existence before removal, guaranteeing `len(graph.getCycles()) == 0` upon exit.

- **Conflating Vertex Appearance Count with In-Degree**:
  - *Pitfall*: Modifying vertex appearance counters (`to_vertex.count -= 1`) inside edge removal methods (`removeEdgeCompletely`). `Vertex.count` tracks symbol frequency across traces, whereas topological connectivity is defined by `graph` and `reverse` adjacency dicts.
  - *Review Check*: Keep vertex occurrence counts distinct from graph adjacency degrees.

- **Silent Parsing Failures on Malformed Inputs**:
  - *Pitfall*: Calling `line.split(",")` on file inputs without handling blank lines or comments, resulting in unhandled `IndexError` or `ValueError`.
  - *Review Check*: Verify that line readers strip whitespace, ignore empty lines, and validate token counts before unpacking tuples.

- **Non-Deterministic Iteration in Output Generation**:
  - *Pitfall*: Iterating over standard Python dictionary keys or sets where ordering is undefined across interpreter runs or environments, leading to non-reproducible binary layouts.
  - *Review Check*: Require explicit secondary sorting (e.g., lexicographical symbol name) for roots and equal-weighted edges.

- **Brittle Workspace Path Traversal**:
  - *Pitfall*: Using rigid relative directory ascendancy like `os.path.join(THIS_DIR, '../../../..')` in `android_build_top()`.
  - *Review Check*: Verify that scripts tolerate execution from the repository root, the script folder, or standalone invocations without broken path assumptions.

## 3. Invariants & Safety Mandates

- **Strict Acyclicity Before Linearization**:
  - The directed graph in `merge_orderfile.py` MUST be a Directed Acyclic Graph (DAG) before DFS serialization (`printOrder()`). Cycles will cause infinite loops or recursion depth exhaustion.
- **Denylist Absolute Invariance**:
  - Any symbol specified in a denylist MUST NEVER appear in an emitted orderfile or pass validation. Denylist checks must be applied at generation time (`create_orderfile.py`) and asserted at validation time (`validate_orderfile.py`).
- **Partial Order Monotonicity**:
  - For any sequence $S = [s_1, s_2, \dots, s_k]$ specified in `--partial`, if symbols $s_i$ and $s_j$ ($i < j$) are present in the orderfile, their indices must strictly satisfy $\text{index}(s_i) < \text{index}(s_j)$. Missing symbols in the orderfile are permitted, but inverted relative order is strictly prohibited.
- **Bit-for-Bit Determinism**:
  - Identical profile, mapping, and weight inputs MUST produce bit-for-bit identical orderfiles across runs and build host machines. All folder globbing must be sorted (`sorted([(f, 1) for f in file_lst])`), and ties in edge weights must resolve stably.
- **Pure Symbol Content in Output Artifacts**:
  - Orderfiles consumed by `lld` must consist solely of valid symbol names, one per line. No file paths, timestamps, comments, or host environment details may be emitted into `.orderfile` outputs.
- **Data Minimization & Public Safety**:
  - No internal corporate links (`go/`), internal bug IDs (`b/`), internal LDAP usernames, or non-public infrastructure configurations may appear in committed scripts, documentation, or test fixtures.

## 4. Verification & Testing Standards

- **Unit Test Coverage (`toolchain/llvm_android/orderfiles/scripts/orderfile_unittest.py`)**:
  - Every change to orderfile scripts must pass the complete unit test suite:
    - `TestCreateOrderfile`: Validates normal extraction, required argument failures, output path customization, leftover symbol handling, denylist exclusion, and `--last-symbol` cutoff boundaries.
    - `TestValidateOrderfile`: Validates baseline orderfile checking, missing argument handling, CSV and file-based partial order verification, allowlist enforcement, denylist rejection, and minimum symbol count (`--min`) constraints.
    - `TestMergeOrderfile`: Tests folder (`^`), file list (`@`), and CSV merge modes; validates cycle removal across simple cycles, long cycles, and multi-cycle topologies; checks dominator tree computations and Graphviz dot export.
- **Negative Testing for Error Paths**:
  - Any new CLI flags, validation rules, or error branches must include explicit negative tests using `assertRaises(subprocess.CalledProcessError)` that assert expected error output messages.
- **Python Lint & Code Hygiene**:
  - All script changes must remain clean under standard Python linters:
    - No unused variables (`unused-variable`).
    - Correct import ordering (`wrong-import-order`).
    - Valid f-string usage (`f-string-without-interpolation`).
    - No redundant parentheses (`superfluous-parens`).
- **Fixture Integrity**:
  - Ensure synthetic test fixtures in `toolchain/llvm_android/orderfiles/test/` (`example.prof`, `example-mapping.txt`, `example.orderfile`, `test/merge-test/*`) remain synchronized with the parser implementations.
